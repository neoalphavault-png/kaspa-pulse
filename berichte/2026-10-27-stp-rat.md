**Advice from Kaspa Pulse before the freeze (Thu 29 Oct 18:00 UTC run)**

**1. A per second step log**
File `go/LOGGING.md`
Missing. `minute.csv` is per minute and `phase.log` is per event, and `submit.jsonl` stays private. So we cannot see whether every sender was sending in every second of a counted minute.
We suggest `logs/sec.csv`, counts only, one row per UTC second from 17:55 to 19:00 UTC. Header `utc_second,step,families,senders_target,senders_on,sent,ok`. Gap seconds stay in with `senders_target` 0. No txid, no address. We then mark a minute as clean only when all planned senders were on for all 60 seconds.
<!-- teil -->
**2. Log lines for sender and node gaps**
Files `plan/PLAN.md` (Senders, Stop, Nodes) and `go/LOGGING.md` (phase.log)
Missing. The node dead rule, the 90,000 mempool skip, a public node dropped for the redeem shape and a family dropped at 17:55 all change the attempt rate, but none of them has a log line. The phase.log example also has no STEP line at 18:40 (3a) and 18:55 (3b) and no line when a gap ends.
We suggest fixed tokens with the actual UTC second, for example `SENDER_OFF sender=desk reason=node_dead`, `SENDER_ON sender=desk`, `NODE_SKIP node=<tag> reason=mempool_90k`, `FAMILY_DROP family=3 reason=no_genesis`, and a STEP line at every boundary. Please also write the counted minutes of each step as exact UTC ranges. We read "count from minute 3" as 18:03 to 18:14, 18:23 to 18:34 and 18:43 to 18:59 (3a and 3b together).
<!-- teil -->
**3. Miner state**
File `plan/PLAN.md` (Nodes)
Missing. The plan does not say whether any miner on your side runs during the hour. A change in your own hashrate moves blocks per minute and inclusion times, and our counter marks such minutes.
We suggest one sentence in the frozen plan. Either "no own miner during the window", or a line `MINER state=on workers=N` in phase.log at every change, with the UTC second.
<!-- teil -->
**4. NTP offsets**
File `go/LOGGING.md` (hwlog, pre-run)
Unclear. The offset is to be logged, but there is no file or format, and it covers only the 2 hwlog machines. `ts` comes from each sender process and `seen_utc` from the coordinator.
We suggest `logs/ntp.csv` with header `utc,machine,offset_ms,source`. One row per machine that stamps `ts` or `seen_utc`, taken at T0 minus 2 h, at T0 minus 5 min and at END plus 1 min. Use the label (desk, mini), not the hostname. Please also state which machine stamps `ts` for the senders that submit to public nodes.

**5. One plan, one header, one reject count**
Files `tn10-covenant-contention-2026-10-29/PLAN.md` and `docs/ORPHAN.md`
