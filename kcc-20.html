What is KCC-20? Kaspa's token standard on layer 1, and every KCC-20 token counted from our own node.

26 October 2026, 12:00 UTC. 240 KCC-20 tokens with 857 unique holders and 4,560 KCC-20 transfers since 22 October 2026, 05:53 UTC, counted by Kaspa Pulse on our own Kaspa node. KCC-20 has been final since 21 October 2026, source the kaspanet/kccs repository.
KCC-20 tokens are new, and most numbers about them come from launchpads and indexers. We count them ourselves, from a Kaspa node we run, and we print the snapshot time next to every number.
The short answer

KCC-20 is the fungible token standard for covenants on Kaspa layer 1. It became Final in the kaspanet/kccs specification repository on 21 October 2026, source the repository's commit history. A KCC-20 balance lives in a covenant output on the chain itself, so a Kaspa node can see every token without an outside indexer.

This page counts, it does not rate. We show no prices, no amounts in any currency and no token we would recommend. A large number of holders says how many owners a token has, nothing more.

A token counts only if at least one of its unspent outputs carries a KCC-20 state that we proved by hash, against the official conformance vectors of the standard. Covenant outputs with any other state do not count.

KRC-20 vs KCC-20

KRC-20 tokens are inscriptions, data written into ordinary transactions and read by an indexer such as Kasplex, so the balances exist in the indexer and not in the chain's rules. KCC-20 tokens sit in covenant outputs on layer 1, so each balance is part of a UTXO and every transfer has to satisfy the covenant script that the network checks. That is why we can count KCC-20 from our own node, while KRC-20 numbers come from an indexer and carry its name as the source.

KRC-20 to KCC-20 migration

As of 29 October 2026, no migration from KRC-20 to KCC-20 can be counted. No project runs a migration on mainnet that is described in an official source and leaves a marker on chain that ties a KCC-20 token to a KRC-20 token. The tools we found are drafts and switched off. 62 of the 240 KCC-20 tokens share a ticker with a KRC-20 token, source kasplex. A shared ticker does not make it the same token. As soon as a migration runs with an on-chain marker, we count it per token on this page.

How we count

  • Snapshot. Our own Kaspa node (rusty-kaspa) reads the set of unspent outputs at a fixed time and reads it a second time from the pruning point forward. Both readings must match.
  • Proof. A covenant output counts as KCC-20 only if its script hash equals the hash of the KCC-20 template with the output's state. The encoding is tested against the official KCC-20 conformance vectors.
  • Holders. Different owners per token. The unique holder count takes every owner once across all tokens.
  • Transfers. Accepted transactions with a KCC-20 transfer tag that create or spend a proven output. Each transaction counts once, and only from the window our own node saw without a gap.
  • Names. Tickers come from KCC-23 metadata or from the data in the token's genesis. They are not unique, so the covenant id stands next to each one.

We publish sums per token and no addresses. Our counting tools are open in our repository.

How often this page updates

Every number carries its snapshot time. A new count needs a full run of our own node, and we start it by hand. The page takes up every new count on its next build, the date above changes with it.

Questions people ask

What is KCC-20?

KCC-20, formally KCC-0020, is the fungible token standard for covenants on Kaspa layer 1. It became Final in the kaspanet/kccs specification repository on 21 October 2026, source the repository's commit history. A KCC-20 balance lives in a covenant output, so a Kaspa node can see it without an outside indexer.

What is the difference between KRC-20 and KCC-20?

KRC-20 tokens are inscriptions, data written into ordinary transactions and read by an indexer such as Kasplex, so the balances exist in the indexer and not in the chain's rules. KCC-20 tokens sit in covenant outputs on layer 1, so each balance is part of a UTXO and every transfer has to satisfy the covenant script that the network checks. That is why KCC-20 can be counted from a node, while KRC-20 numbers come from an indexer and carry its name as the source.

How many KCC-20 tokens are there?

240 KCC-20 tokens at 26 October 2026, 12:00 UTC, with 857 unique holders and 2,646 holder outputs, counted by Kaspa Pulse on our own Kaspa node. A token counts only if at least one unspent output carries a KCC-20 state that we proved by hash.

Can KRC-20 tokens migrate to KCC-20?

Not in a way anyone can count yet. As of 29 October 2026 no project runs an officially described migration on mainnet that leaves a marker on chain. 62 KCC-20 tokens share a ticker with a KRC-20 token, source kasplex, and a shared ticker does not make it the same token.

Is KCC-20 a change to Kaspa's consensus?

No. KCC-20 is token logic on top of covenants. The covenants themselves came with the Toccata hard fork, and KCC-20 describes how a token keeps its state and moves inside them. A wallet or explorer that follows the specification can read a KCC-20 balance from the chain.
